## 2. How to run the pending checks (owner)

Start the capture, then switch to the Claude window and act; the capture runs 25 s from its start (pass `-Seconds 40` for more). Every run appends to `tools\_capture.log`; copy the block into section 3.

```
explorer.exe "C:\Projects\ClaudeCodePlus\tools\Capture-Documents.cmd"
```

- **A, a new session's start.** From the new-session screen pick a folder, type a short prompt and send it; wait for the reply. Expected in the log: the session document's URL on the new-session screen (a `local_` id already, or another route), the documents during "Starting session" (name length, `titled=yes/no`, the URL) and after the reply, and the newest record's `created`, `focused`, `cli`, `title` columns tick by tick. The overlay must show nothing for the new session until its own `local_<id>.json` appears, never another session's figures.
- **B, the no-folder screen.** Open the new-session screen with no folder picked and leave it in front for a few seconds. Expected: the `row:` line with the composer's buttons (is `Environment: …` there with no folder?) and the document's URL. The diagnostics file `%LOCALAPPDATA%\ClaudeCodePlus\diagnostics.log` gets a line after about five seconds only if the button found no anchor.
- **D, `/clear` in a throwaway session.** In a session with the new mod (one started after the plugin update, or after `/reload-plugins` typed in it), type `/ctxbar`, then `/clear`, then `/ctxbar` again. Expected: the second line of `/ctxbar` ("context-bar: session <engine id>, desktop <local_ id>, file <path>") shows a new engine id and the same desktop id and file after `/clear`; the overlay's line survives `/clear` (hidden only while the engine has no reading, then "— — / 1M", then the figures). Outside the session, `~\.claude\sessions\<pid>.json` shows the new `sessionId` under the same `hostSessionId`.
