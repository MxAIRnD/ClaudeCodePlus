Research notes, 2026-10-15 (official docs, precedents in other Claude Code tools, read-only UI Automation probes on the MSI laptop with app 2.37337.1).

**Probably covered for current builds.** Commit f833f53 added a third anchor for the newer layout (app 2.37337.1): the `Environment: …` chip joined with the buttons that follow it on its row. On that layout the environment chip belongs to the composer's bottom row whether or not a folder is picked, so the button should appear with no folder too. Unverified: one UI Automation capture of the no-folder screen on 2.37337.1 (button names and bounds) settles it. The `No folder` fallback proposed above is then needed only for the older layout (2.26454.2), if it must stay supported.

**No sturdier anchor than accessible names exists.** Chromium maps the UI Automation `AutomationId` to the HTML `id` attribute only, and this app's ids are generated per render (`_r_4n4_` and `base-ui-_r_4ng_` on the footer chips, the React `useId` / Base UI style), so they change between mounts. `data-testid` is not exposed to UI Automation at all, and `ClassName` is the HTML `class` attribute, here a Tailwind utility string. Microsoft's own guidance: `AutomationId` identifies an element among its siblings and needs container scope. So name anchors with structural fallbacks, which `ChipRowLocator` already does, remain the norm.

**What to add instead: a self-diagnostic.** When a Claude window is in front and no anchor is found, log once per app version the names and bounds of the buttons on the lowest composer row, with the app version (readable from the shell document's URL, `…/WindowsApps/Claude_2.37337.1.0_x64__…/app/resources/app.asar/…`, or from the process image path). A renamed chip then becomes a one-line report instead of a silent disappearance. Optionally a name table keyed by app version (and by locale: the app ships 43 locale files; whether the chip names are translated with the UI language is unknown).

**Drift already observed:** on 2.37337.1 the model chip's name reads `Model: Fable 5.1 Max` (the effort word is part of the name); the `Model: ` prefix match in `FooterLocator` survives it.
